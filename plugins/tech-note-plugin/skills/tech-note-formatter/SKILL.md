# 技術調査メモへの変換

長い技術解説 md を、その技術を知らない開発者が上から読めば分かる短いメモ（140行・4,000字前後）に作り直す。網羅はしない。落とした情報は元ファイルに残る。

この型は、ユーザーが選んだお手本4本から取っている。`references/examples/` があれば、書く前に対象に近い1本を読む。なければ、このファイルだけで書ける。

| お手本 | 近い対象 |
|---|---|
| `workload-identity-federation.md` | 認証・認可の仕組み、クラウドの機能 |
| `sso-entra-id.md` | プロトコル＋製品（登場人物や呼び名が多いもの） |
| `terraform.md` | ツール・CLI（コマンドと設定ファイルがあるもの） |
| `transformer.md` | アルゴリズム・モデル・論文（式と数値例があるもの） |

## 出力

- `<元の名前>-note.md` を元ファイルと同じフォルダに書く。元ファイルは上書きしない
- ユーザーが出力先や名前を指定したら、それに従う
- 疑問リストは頼まれたときだけ作る（「疑問リスト」の節）
- 複数ファイルを渡されたら、1ファイルずつ手順を最後まで回す

## 手順

### 1. 元ファイルを最後まで読む

一度に読めない長さなら、分割して全部読む。読みながら次を拾う。

- 一言定義（何を・どうする・何の仲間か）と、従来のやり方から何が変わるか
- 全体の構造（登場する部品・人物と、その関係）
- 仕組みの核（これがないと誤解する流れ・式・データ形式）
- 具体例にできるコード・設定・数値例
- 製品・クラウド・系統ごとの違いと、比べられている類似技術
- 事故（データ消失・乗っ取り・全面停止・意図しない作り直し）につながる注意点
- 基準日（元の作成日や確かめた時点）、調査対象のバージョン、出典

### 2. 行き先を決める

| 元の内容 | 行き先 |
|---|---|
| 〜とは・ひとことで言うと・特徴 | 概要の1段落目 |
| 登場の背景・従来の問題 | 概要の2段落目（1〜2文）。従来との違いを3〜4観点で比べられるなら比較表も |
| 前提知識（用語・登場人物の呼び名） | 初出の括弧で一言。呼び名がプロトコルや製品で変わるなら対応表の節 |
| アーキテクチャ・構成要素 | 全体構造の節（Mermaid＋表か箇条書き） |
| 処理の流れ・内部動作・計算式・データ形式 | 仕組みの節（2〜3節） |
| コード例・設定例・数値例 | 具体例（1〜2個） |
| 製品・クラウドごとの対応、類似技術・派生・後継との比較 | 対応表・比較表の節 |
| セキュリティ・ベストプラクティス・ハマりどころ | 注意点・運用の急所。いちばん危ない1点は関係する節の `[!WARNING]` |
| 参考文献 | 参考（脚注で4〜5件） |
| 目次・年表・まとめ・よくあるエラーの切り分け・導入手順・CI/CD の全文・料金・エディション比較・機能やパラメーターの一覧・新機能の列挙・実装の全文 | 捨てる。理解に要る1点だけ、表の1行か注意点に残す |

迷ったら「これがないと、知らない開発者が仕組みを誤解するか、事故を起こすか」で決める。どちらでもなければ捨てる。

残す話題でも、添える細目（数値・設定名・パラメーター・URL・ヘッダー名・版ごとの違い）は、その仕組みの理解か事故の回避に要る1〜2個に絞る。細目を並べるほど、読み手はどれが要点か分からなくなる。載せなかった細目は元ファイルに残っている。

### 3. メモを書く

「型」と「書き方ルール」に従う。変換では次も守る。

- **元にない事実を足さない**。変換であって再調査ではない
- 数値・バージョン・日付は元の表記のまま使う
- 元の章立ては写さない。型の順（全体 → 部品 → 動き → 具体例 → 違い → 注意点）に並べ替える。元は「機能ごと」の章立てが多く、そのままでは知らない人が上から読めない
- 元のコードは縮めて使う。動かせる環境なら動かし、数値例は検算する。動かせないなら元の出力をそのまま使い、報告で未実行と伝える
- 長さの目安は140行・4,000字前後（お手本4本は129〜172行、3,600〜4,000字。字数はコード・Mermaid・脚注の定義・空白を除いて数える）。上限は180行・4,300字。行数だけを絞ると1行が長くなり、読む量は減らないので、字数でも見る。目安を超えたら手順2の「捨てる」に戻って削る。残す優先順は、一言定義 → 全体構造 → 仕組みの核 → 具体例1つ → 事故につながる注意点

### 4. 検査する

1. 付録の検査スクリプトを作業用の一時ファイル（例: `check_note.py`）に書き出し、メモを渡して実行する
2. ERROR がなくなるまで直す。WARN は読んで判断する
3. Mermaid は構文を見直す。描画できる環境なら描画して確かめる
4. スクリプトで見られない点を自分で確かめる
   - 見出しと太字だけを拾って、何の技術でどう動くかが分かるか
   - 専門用語に、初出で一言添えてあるか
   - `[!WARNING]` が、事故に直結する1点だけに使われているか
   - 元にない事実・数値が入っていないか

Python を実行できない環境では、見出しの順序、です・ます、使わない表現、脚注の対応を目で確かめる。

### 5. 報告する

ユーザーには次だけを短く伝える。

- 出力したファイルのパス
- 行数の変化（元 → メモ）
- 捨てた主な内容（2〜3行）。元ファイルに残っていることも添える
- 未実行のコードや検算していない数値があれば、そのこと

## 型

`<…>` を差し替える。中間の `##` の名前と数は対象に合わせて決める。

````markdown
# <技術名>

- 基準日：<YYYY-MM-DD>（<製品> <バージョン> 時点）

## 概要

<技術名>（<略称>）は、<何を・どうする（いちばんの特徴を**太字**に）><分類>。

<従来のやり方の何が困っていて、この技術で何が変わるか。1〜2文>

| 観点 | <従来のやり方> | <この技術> |
| --- | --- | --- |
| <観点> | <…> | **<…>** |

## <全体の構造>

```mermaid
flowchart LR
    <部品と関係>
```

| 構成要素 | 実体 | 役割 |
| --- | --- | --- |
| **<部品>** | <…> | <…> |

## <仕組み>

<この節で分かることを1〜2文>

### <段階や論点>

1. **<段階>**：<何が起きるか>

> [!WARNING]
> <事故に直結する1点。なぜ起きて、何が壊れるか>

## <具体例>

<何を示す例かを1文>

```<lang>
<元の例を縮めたもの。要点はコメント>
```

## <製品・系統ごとの違い>

| 役割 | <A> | <B> |
| --- | --- | --- |
| **<役割>** | <…> | <…> |

## 注意点・運用の急所

- **<気をつけること>**：<仕組みのどこから来るか、どうするか。1〜3文>[^1]

## 参考

[^1]: <発行元>. *<タイトル>.* <URL>
````

### 各部の書き方

- **ヘッダー**: H1 は技術名だけ。frontmatter は付けない。基準日は元の作成日（元が確かめた時点）。バージョンがある対象は括弧で版を添える（例: `- 基準日：2026-11-08（Terraform 1.17.1 時点）`）
- **概要**: 1段落目は「<技術名>は、〜する<分類>。」の一言定義で、いちばんの特徴を太字にする（例: 「クラウド外のプログラムが、**長期の秘密鍵を一切持たずに**クラウド API を呼ぶための認証の仕組み」）。2段落目は従来との違いと、それで何ができるようになるか。比較表は、従来のやり方と3〜4観点で比べられるときだけ置く（お手本では WIF と Transformer だけ）
- **中間の節**: `##` を4〜6個。名前は扱う対象そのものにし（例: 「JWT（JSON Web Token）」「State 管理と機密情報」）、括弧で位置づけや問いを補ってよい（例: 「Core・Provider・State（全体構造）」「3層のセッションと PRT（なぜ2回目から聞かれないか）」）。`###` は1つの `##` に3個まで
- **具体例**: 仕組みを説明している節の中に置くか（Terraform の HCL、Transformer の数値例）、「<A> → <B> の設定例」の節にする（WIF）。1〜2個
- **製品・系統ごとの違い**: 対応表か比較表にまとめる。製品ごとに節を分けない（同じ構成要素の名前違いを並べると、共通の仕組みが見える）
- **注意点・運用の急所**: 名前は固定で、「参考」の直前に置く。「- **見出し語**：説明」の箇条書きを2〜4項目（多くても5）。1項目は200字前後まで（お手本はおおむね100〜200字）。理由は仕組みで出てきた動きで言い、どうするかまで書く。運用・セキュリティの話はここにまとめる
- **参考**: 脚注の定義だけを並べる。脚注は出典専用で、根拠になる文や表のセルの直後に `[^n]` を付ける。番号は本文の登場順

## 書き方ルール

### 形式の選び方

| 書く内容 | 形式 |
|---|---|
| 同じ観点で並べて比べる・対応させる（従来との比較、構成要素、クレームや記号の意味、製品ごとの対応） | 表。1列目は太字の項目名、列は6つまで |
| 順序のある処理 | 番号付きリスト「1. **段階**：何が起きるか」 |
| 3者以上のやり取り | Mermaid のシーケンス図 |
| 構造・部品の関係 | Mermaid の flowchart ＋ 部品の表か箇条書き |
| 並列の要点・注意点 | 箇条書き「- **見出し語**：説明」 |
| 理由・節の導入 | 文章（1段落3文まで） |
| データ形式・パス | `text` のコードブロック |
| 式 | `$…$`・`$$…$$` |
| 事故に直結する1点 | `> [!WARNING]` |
| 表の記号の意味、本筋から外れる関連情報 | `> [!NOTE]` |

数はお手本の実績から決めている。ふつうは表4〜5つ、Mermaid 1〜2つ、コールアウト（WARNING と NOTE の合計）1つ、Mermaid 以外のコードブロック1〜2つ、脚注4〜5件。上限は表5つ、Mermaid 2つ、コールアウト2つ、コードブロック4つ。上限まで使わなくてよい。部品が増えるほど、どれが要点か読み手に伝わりにくくなる。流れや理由は表に押し込まない。表は読む順が決まらず、理由を書けないため。

### 文体

- 常体か体言止め。です・ます調は使わない
- 1文に1つのこと。長くなったら箇条書きに割る
- 主語と結論を文頭に置く
- 太字は、一言定義の核、表の1列目、箇条書きの見出し語、結論の句に絞る
- 専門用語は初出で括弧の一言を添える（例: 「公開鍵一覧（JWKS）」「手作業変更によるずれ（**ドリフト**）」）。略語は「Workload Identity Federation（WIF）」の形。用語集は作らない
- 時点で変わる情報（GA・非推奨・既定化・開発終了）は版か日付を添える（例: 「1.11 で GA」「2025-12 に開発終了」）
- 同じ情報を2回書かない

### 使わない表現

| NG | 代わり |
|---|---|
| 〜することができます | 〜できる |
| 〜というものがあります | （削除して名詞から書く） |
| なお、〜 / ちなみに、〜 | 箇条書きの1項目にする |
| 非常に重要な役割を果たします | 何をするかを具体的に書く |
| 〜について見ていきましょう | （削除） |
| まとめると〜 / いかがでしたか | （削除） |

## 疑問リスト（頼まれたときだけ）

元が答えていない問いだけを、メモと同じ場所の `<メモのファイル名>-questions.md` に書く。答えを推測で書き足さない。材料は、時点つき・プレビューの情報、元が断定を避けた主張、元の中で食い違う記述、未検証のコードや数値。

```markdown
# <技術名>: 疑問リスト

- [ ] <疑問（1行）>
```

## 付録: 検査スクリプト

```python
"""調査メモの機械チェック。使い方: python3 check_note.py <x>-note.md [<x>-note-questions.md]"""
import re, sys

FIRST, CAUTION, LAST = "概要", "注意点・運用の急所", "参考"
DROP = ["目次", "TL;DR", "用語集", "まとめ", "年表", "歴史", "よくあるエラー"]  # お手本の型にない節
MAX_LINES = 180  # ファイル全体の行数（目安140行。お手本4本は129〜172行）
MAX_CHARS = 4300  # 本文の字数。コード・Mermaid・脚注の定義・空白を除く（目安4,000字。お手本4本は3,600〜4,000字）
MAX_BULLET = 250  # 注意点の1項目の字数（目安200字。お手本は75〜241字）
MAX_TABLES, MAX_COLS = 5, 6  # 表の数（お手本は各5つ）と列数（数値例の表で6）
MAX_MERMAID, MAX_CALLOUTS, MAX_CODE = 2, 2, 4  # Mermaid・コールアウト・Mermaid 以外のコードブロック
NG = ["ことができ", "というものがあ", "なお、", "ちなみに、", "非常に重要", "見ていきましょう", "まとめると", "いかがでしたか"]
DESU = re.compile(r"(です|(?<![すさ])ます|でした|ました|ません|ましょう)(。|$|）|」|\))")  # なりすます等は除外
out = []

def plain(s):  # 文の数を数えるときに邪魔な記法（コード・数式・脚注記号）を畳む
    s = re.sub(r"`[^`]*`", "C", s)
    s = re.sub(r"\$[^$]+\$", "M", s)
    return re.sub(r"\[\^\w+\]|\*\*", "", s)

def check_note(path):
    lines = open(path, encoding="utf-8").read().rstrip("\n").split("\n")
    E = lambda n, m: out.append(f"ERROR {path}:{n}: {m}")
    W = lambda n, m: out.append(f"WARN {path}:{n}: {m}")
    if not lines[0].startswith("# "): E(1, "1行目は `# <技術名>`（frontmatter は付けない）")
    nxt = next(((i, l) for i, l in enumerate(lines[1:], 2) if l.strip()), (2, ""))
    if not re.match(r"- 基準日：\d{4}-\d{2}-\d{2}", nxt[1]): E(nxt[0], "H1 の次は `- 基準日：YYYY-MM-DD` の行")
    sec, heads, fence, para = None, [], None, []
    tables = mermaid = code = callouts = chars = 0
    defs, refs, caution_bullets, no_url = {}, set(), 0, 0
    for n, line in enumerate(lines + [""], 1):
        if line.startswith("```"):
            if fence is None:
                fence = line[3:].strip()
                if fence == "mermaid": mermaid += 1
                else: code += 1
            else: fence = None
            continue
        if line.strip() == "$$": fence = None if fence == "$$" else "$$" if fence is None else fence; continue
        if fence is not None: continue
        if not re.match(r"\[\^\w+\]:", line): chars += len(re.sub(r"\s", "", line))
        if line.startswith("# ") and n != 1: E(n, "H1 は1行目の1つだけ")
        if line.startswith("## "):
            sec = line[3:].strip(); heads.append((sec, n))
            if any(w in sec for w in DROP): E(n, f"お手本の型にない節: {sec}（捨てるか、要る1点だけ本文に入れる）")
            continue
        if re.fullmatch(r"\*\*[^*]+\*\*[:：]?", line.strip()): E(n, "太字だけの行を見出し代わりにしている（### にする）")
        if re.match(r">\s*\[!\w+\]", line):
            callouts += 1
            if sec == CAUTION: W(n, "注意点の節ではコールアウトを使わない（箇条書きにする。[!WARNING] は関係する説明の直後へ）")
        if sec == CAUTION and line.startswith("- **"):
            caution_bullets += 1
            if len(re.sub(r"\[\^\w+\]", "", line)) > MAX_BULLET: W(n, f"注意点の1項目が{MAX_BULLET}字を超える（理由と対処を1つずつに絞る）")
        d = re.match(r"\[\^(\w+)\]:\s*(.*)", line)
        if d:
            defs[d.group(1)] = n
            if sec != LAST: E(n, "脚注の定義は「参考」の下にまとめる")
            if "http" not in d.group(2): no_url += 1
        else:
            refs.update(re.findall(r"\[\^(\w+)\]", line))
            if sec == LAST and line.strip() and not line.startswith("- "): E(n, "「参考」には脚注の定義だけを置く")
        if any(w in line for w in NG): E(n, "使わない表現: " + ", ".join(w for w in NG if w in line))
        if DESU.search(re.sub(r"`[^`]*`", "", line)): E(n, "です・ます調")
        if re.match(r"\|\s*:?-", line):
            tables += 1
            continue
        if line.startswith("|") and len(line.strip().strip("|").split("|")) > MAX_COLS: W(n, f"表の列が{MAX_COLS}つを超える（比べる相手か観点を絞る）")
        if line.strip() and not re.match(r"\s*(-|\d+\.|\||>|\[\^|#)", line): para.append(line)
        elif para:
            if sum(plain(p).count("。") for p in para) > 3: W(n - 1, "1段落が3文を超える（箇条書きか表に割る）")
            para = []
    if no_url: W(1, f"URL のない脚注が{no_url}個（脚注は出典に使う。補足は本文か [!NOTE] に書く）")
    names = [h for h, _ in heads]
    if not names or names[0] != FIRST: E(1, f"最初の ## は「{FIRST}」")
    if not names or names[-1] != LAST: E(1, f"最後の ## は「{LAST}」")
    if CAUTION in names:
        if len(names) < 2 or names[-2] != CAUTION: E(1, f"「{CAUTION}」は「{LAST}」の直前に置く")
        if caution_bullets == 0: W(1, f"「{CAUTION}」が「- **見出し語**：説明」の箇条書きになっていない")
    else: W(1, f"「{CAUTION}」の節がない（事故につながる点が元に本当にないか確かめる）")
    mid = len([h for h in names if h not in (FIRST, CAUTION, LAST)])
    if not 3 <= mid <= 6: W(1, f"概要と注意点のあいだの ## が{mid}個（お手本は4〜6個）")
    if len(lines) > MAX_LINES: W(len(lines), f"{len(lines)}行（目安140行・上限{MAX_LINES}行。捨てる基準で削る）")
    if chars > MAX_CHARS: W(1, f"本文が{chars}字（目安4,000字・上限{MAX_CHARS}字。コード・Mermaid・脚注の定義・空白を除く。捨てる基準で削る）")
    if tables > MAX_TABLES: W(1, f"表が{tables}個（目安{MAX_TABLES}個まで。流れや理由は箇条書きか文章にする）")
    if mermaid > MAX_MERMAID: W(1, f"Mermaid が{mermaid}個（目安{MAX_MERMAID}個まで）")
    if callouts > MAX_CALLOUTS: W(1, f"コールアウトが{callouts}個（[!WARNING] と [!NOTE] で{MAX_CALLOUTS}個まで）")
    if code > MAX_CODE: W(1, f"Mermaid 以外のコードブロックが{code}個（具体例は1〜2個に絞る）")
    for r in sorted(refs - defs.keys()): E(1, f"脚注 [^{r}] の定義がない")
    for r in sorted(defs.keys() - refs): E(defs[r], f"脚注 [^{r}] が本文で参照されていない")

def check_questions(path):
    lines = open(path, encoding="utf-8").read().split("\n")
    if not lines[0].startswith("# "): out.append(f"ERROR {path}:1: 1行目は `# <技術名>: 疑問リスト`")
    for n, line in enumerate(lines[1:], 2):
        if line.strip() and not line.startswith("- [ ] "): out.append(f"ERROR {path}:{n}: 疑問は「- [ ] 」の1行で書く")

for p in sys.argv[1:]:
    (check_questions if p.endswith("-questions.md") else check_note)(p)
print("\n".join(out) or "OK")
sys.exit(1 if any(o.startswith("ERROR") for o in out) else 0)
